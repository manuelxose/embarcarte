## 1. Mode contract

Four modes are defined. The selector is scoped to the design system's own host
element; there is no `:root`, `html` or `body` override anywhere in the design
system.

| Mode | Label | Context | `color-scheme` | Status | Selector | Colour roles |
|---|---|---|---|---|---|---|
| `web-light` | Corporate web (light) | `corporate` | `light` | `EXISTING_MEASURED_BASELINE` | `marea-theme` (default host state) | 33 |
| `instrument-day` | Instrument — day | `instrument` | `light` | `INTERNAL_PROPOSED` | `marea-theme[data-marea-mode='instrument-day']` | 33 |
| `instrument-sunlight` | Instrument — sunlight | `instrument` | `light` | `INTERNAL_PROPOSED` | `marea-theme[data-marea-mode='instrument-sunlight']` | 33 |
| `instrument-night` | Instrument — night | `instrument` | `dark` | `INTERNAL_PROPOSED` | `marea-theme[data-marea-mode='instrument-night']` | 33 |

Declared applicability, quoted from `mode-contracts.json`:

- `web-light` — "Isolated corporate web components on the existing light
  EMBARCARTE visual system. The live site itself is not restyled."
- `instrument-day` — "Internal software specimens for bridge daylight use. Not a
  hardware readability claim."
- `instrument-sunlight` — "Internal high-ambient-light software specimen. Glare
  readability is NOT validated; hardware validation is BLOCKED."
- `instrument-night` — "Internal watchkeeping software specimen. Night-vision
  performance is NOT validated. No `#000000` canvas and no `#ffffff` text."

The theme host (`src/app/marea-design-system/theme/marea-theme.ts`) sets
`[attr.data-marea-mode]` from its `mode` input (default `'web-light'`), derives
`data-marea-context` (`instrument` when the mode starts with `instrument-`,
otherwise `corporate`), sets `[attr.lang]` from its `locale` input and renders
projected content only. Components inherit the custom properties from the nearest
`<marea-theme>` host; nothing is inherited from the document root.

## 2. Why day, sunlight and night are derived, not inverted

Night is a **separately measured palette**, not a CSS filter, `invert()` or
hue-rotation of the day palette. The reasons, all recorded in MC-04:

1. **Halation floor.** The night mode forbids a pure-black canvas and pure-white
   text because high-contrast white on black blooms for a dark-adapted eye. MC-04
   §5.8 states the rule; `color-roles.json` encodes it as `forbiddenValues`
   (`instrument-night: ["#000000", "#ffffff"]`) and the validator enforces it as
   check `MC17-03` — recorded result: "night palette avoids #000000 and #ffffff".
2. **Different semantic goals per mode.** Day maximises separation on light
   surfaces; sunlight increases ink darkness and reduces the lightest surfaces to
   hold up under glare; night lowers absolute luminance while keeping every status
   distinguishable. A mechanical inversion cannot change the *roles* (for example
   "canvas is the darkest surface" inverts to "canvas is the lightest"), which is
   why each mode declares its own 33 values.
3. **Status hues are re-tuned, not flipped.** `stateCritical` goes `#b4423a`
   (web-light) → `#a32b22` (day) → `#8f1a12` (sunlight) → `#ff9b8f` (night);
   `stateSafe` goes `#27775c` → `#1f5f49` → `#10513c` → `#7bd8b0`. The night
   values are lighter/desaturated so they remain legible without a bright fill.
4. **Time and state are unchanged by the mode.** `formatAge()` and the numeric
   contract (`tabular-nums`, U+2212) are mode-independent; changing the theme
   never changes a value or an age.

**No performance claim follows from this.** The modes were never rendered on a
marine display; the sunlight and night palettes are computed and specified only.

## 4. Contrast methodology

The ratio is computed by `scripts/check-marea-design-system.mjs` from the
**declared token values** (not from rendered pixels):

```js
linear = c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4   // per sRGB channel /255
L      = 0.2126*R + 0.7152*G + 0.0722*B
ratio  = (max(L1,L2) + 0.05) / (min(L1,L2) + 0.05)
```

Pairs come from the token contract's declared pair groups
(`color-roles.json` `contrastPairs`), expanded per mode:

| Pair group | Foregrounds | Backgrounds | Kind | Min ratio |
|---|---|---|---|---|
| `text-on-surfaces` | 11 text/data/state/action roles | canvas, surface, surfaceRaised, fieldSurface | text-normal | 4.5 |
| `on-accent-on-fills` | `textOnAccent` | action, actionHover, stateCritical, stateWarning, stateSafe | text-normal | 4.5 |
| `status-text-on-status-surface` | 5 state roles | their matching status surface | text-normal | 4.5 |
| `action-text-on-quiet-surface` | `action` | `actionQuietSurface` | text-normal | 4.5 |
| `internal-banner-text` | `internalBannerText` | `internalBannerSurface` | text-normal | 4.5 |
| `disabled-text-internal-target` | `disabled` | disabledSurface, canvas, surface | text-disabled-internal | 3 |
| `focus-ring-on-surfaces` | `focusRing` | canvas, surface, surfaceRaised, fieldSurface | focus | 3 |
| `focus-ring-on-fill` | `focusRingOnFill` | action, actionHover, stateCritical, stateWarning | focus | 3 |
| `control-boundary` | `borderStrong` | canvas, surface, fieldSurface | ui | 3 |
| `chart-supporting-cues` | chartGrid, chartLine | canvas, surface | ui | 3 |

Measured volume: **296 pair/mode measurements** = 74 distinct pairs × 4 modes
(224 text-normal, 32 focus, 28 ui, 12 disabled-internal). Recorded status: `PASS`,
**0 failures**. The artifact is rewritten on every `npm run test:design-system`
run, so the numbers in §5 are the values of the recorded run and must be re-read
from the file after any token change.

## 7. Night-mode restrictions and state encoding

- **Forbidden values:** `instrument-night` may not use `#000000` (canvas) or
  `#ffffff` (text). Enforced by check `MC17-03` over every colour role, recorded
  PASS. Night `canvas` is `#0d1b26` and night `textPrimary` is `#8fd3f5`.
- **Status is never colour-only.** `color-roles.json` `dataStatusSemantics`
  declares six tones, each with a colour role, a status surface role, a **shape**
  and `requiresText: true`. `marea-status-badge` requires a `label` input, so an
  icon-only or colour-only status chip cannot be constructed through the API
  (check `MC17-18` PASS: "6 status tones require text and a shape icon").
- **Live regions:** continuous instrument values are not announced; status
  components expose `live: 'off' | 'polite' | 'assertive'` with `off` as the
  default, so an alarm has to opt in deliberately.
