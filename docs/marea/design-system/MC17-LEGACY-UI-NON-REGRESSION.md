## 3. Method

1. Resolve the base commit `6d8287c…` with `git rev-parse`.
2. List tracked files at that commit with `git ls-tree -r --name-only`.
3. For each watched path, read the blob from the **Git object database**
   (`git show <commit>:<path>`), never from the working tree.
4. Record the Git blob SHA-1, the SHA-256 of the blob, and the byte length.
5. The validator (`MC17-28`) recomputes the working-tree file hash and compares it to the
   baseline SHA-256.

### 3.1 CRLF canonical comparison

Git stores text blobs with LF endings. A Windows checkout may materialise CRLF, which would
otherwise look like a modification. The validator handles this in `canonical()`:

```js
const text = buffer.toString('latin1');
return text.includes('\u0000') ? buffer : Buffer.from(text.replace(/\r\n/g, '\n'), 'latin1');
```

- Text files: CRLF is normalised to LF before SHA-256, so a CRLF checkout compares equal.
- Binary files (any NUL byte): hashed raw, no normalisation.
- The baseline itself stores the SHA-256 of the LF blob read from Git.

This is the exact reason a Windows working tree can pass `MC17-28` without a false positive.
It does not mean the working-tree bytes are literally identical to the blob; it means the
CRLF-canonical content is.

## 7. What the baseline proves — and what it does not

Proven (when `npm run test:design-system` passes):

- Each watched file exists and its CRLF-canonical SHA-256 equals the base-commit blob.
- No watched file was silently edited, deleted or replaced.
- The public file set did not grow and contains no MAREA-named asset.
- The route registry still has 23 proposed routes and none was added to the Angular router.
- Public metadata files (`src/index.html`, `robots.txt`, `site.webmanifest`, `og-image.png`,
  `favicon.svg`) match the baseline (`MC17-30`).

**Not proven by the baseline:**

- Runtime visual equivalence. Identical bytes to the base commit prove no UI file changed
  in MC-17; they do not prove that the running site matches a visual reference, that fonts
  render identically, or that the baseline commit itself was visually approved.
- Behaviour under hydration, responsive layout or assistive technology.
- That the deployed website (if any) is the same artifact.
- That third-party services, CDNs or assets behave identically.
