This document reconciles every MC-04 token family with what the MC-17 token layer
actually declares. It states value changes, the provenance status of each value
and what was deliberately **not** changed.

## 1. Reconciliation method

1. Each MC-04 value is read from `marea-instrument-tokens.proposed.json` and the
   two system documents.
2. Each MC-17 value is read from `marea-design-tokens.source.json` and its
   flattened provenance in `data/token-source-map.json` (262 rows: 132 colour,
   58 typography, 72 layout).
3. Each row carries a `sourceTokenId`. The convention is
   `MC04:/modes/<mode>/tokens/<role>` for a value inherited from the MC-04 token
   contract, `MC04:/<group>/<path>` for a typography/layout value, and
   `DERIVED:/<origin>` for a value that does not exist in MC-04 and was added by
   the implementation layer. `WCAG22:/<criterion>` marks a normative citation.
4. A value is only described as *changed* when the token id is the same and the
   literal differs. A role that MC-04 never defined is *added*, not changed.

Status vocabulary used in the tables (taken verbatim from the datasets):

| Status | Meaning |
|---|---|
| `EXISTING_MEASURED_BASELINE` | The value is the measured MC-04 web-light baseline; MC-17 re-exposes it, does not invent it |
| `INTERNAL_PROPOSED` | MC-04 proposed instrument value, still a proposal; no hardware validation |
| `DERIVED_INTERNAL` | MC-17 implementation value with no MC-04 token of the same id |
| `NORMATIVE_WCAG_22_AA` | Value fixed by a WCAG 2.2 criterion, not by design preference |
| `INTERNAL_DESIGN_GOAL` | Internal target that is explicitly **not** a conformance requirement |

All other values are literal copies of the MC-04 proposal. Nothing was tightened
silently; the four refinements and the added `focusRingOnFill` are the complete
delta (`COLOUR-SYSTEM.md` §11 lists the same five).

## 8. Limits of this reconciliation

- It reconciles **values and provenance**, not rendering. No browser sampled the
  computed colours.
- Instrument day/sunlight/night remain software specimens; hardware validation is
  `BLOCKED`, so no value here is validated for a marine display.
- The MC-04 internal contrast targets (text ≥5:1, cockpit ≥7:1) are **not** all
  met by the web-light baseline: F-4/F-5/F-6/F-7 record misses between 4.71:1 and
  5.55:1. The MC-17 contrast gate declares the WCAG AA minima (4.5:1 text, 3:1 UI
  and focus), so a "PASS" in `contrast-evidence.json` means AA at the declared
  thresholds — see D05 §5 for the measured rows.
- Any token change invalidates this reconciliation; regenerate with
  `npm run build:tokens` and re-run `npm run test:design-system`.
