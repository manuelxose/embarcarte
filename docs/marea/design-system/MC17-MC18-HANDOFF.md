## 6. Responsive conventions

| Convention | Token / value |
|---|---|
| Minimum reflow floor | 320px (`--marea-bp-320`, WCAG 1.4.10) |
| Breakpoints | 320, 360, 390, 480, 768, 900, 1024, 1160, 1440 |
| Container | narrow 800px, default 1160px, wide 1360px |
| Gutters | 16px below 768, 24px 768-1159, 32px at 1160+ |
| Grid | 12 reference columns; components use fluid `minmax()` grids |
| Reading measure | 68ch |
| Control heights / minimum target | 32 / 40 / 48px; 24×24px minimum (`--marea-touch-target-min`), 44px wet/glove goal |
| Motion | 120-200ms, standard easing, disabled on `prefers-reduced-motion` |

Mobile-first is the rule. The Playwright responsive spec verifies 320, 360, 390, 768, 1024
and 1440 with no page-level horizontal overflow and with dense tables inside labelled,
focusable scroll regions. At authoring time that suite was not clean (no responsive
screenshots committed), so treat the conventions as documented, not runtime-certified.

## 7. Accessible navigation and disclosure patterns

| Pattern | Component | Contract |
|---|---|---|
| Responsive navigation | `marea-responsive-nav` | Below 1024px a single native toggle (`aria-expanded`, `aria-controls`); Escape closes and returns focus to the toggle; link click closes; from 1024px the toggle is hidden and the list is horizontal; no focus trap and no overlay; current page uses `aria-current="page"` plus text decoration |
| Simple disclosure | `marea-disclosure` | Native `<details>/<summary>`; Angular `open` input stays authoritative; Enter/Space handled natively |
| Single-open accordion | `marea-accordion` | Native `details[name]` exclusivity; at most one open item |
| Tabs | `marea-tabs` / `marea-tab-panel` | Roving tabindex, Arrow/Home/End, `aria-selected`, `aria-controls`, `aria-labelledby`, one tab stop |
| Focus | token layer | 3px solid focus ring, 2px offset and inset variant; `:focus-visible` on all interactive components (`MC17-15`) |
| Disabled control | `marea-button` | `aria-disabled` + `aria-describedby` reason + keyboard discoverable + activation blocked |

The catalogued keyboard spec exercises these with real Tab/Enter/Space/Escape/Arrow keys and
checks the absence of a keyboard trap. The public site's existing skip link and mobile menu
are covered separately by `e2e/accessibility.spec.ts`.

## 11. SSR / hydration contract

The design-system code is designed to be SSR-safe and hydration-stable by construction, but
the internal catalogue is client-side only, so **no SSR or hydration measurement of these
components exists**. The properties below are code facts, not measured results.

Evidence-based properties:

- `MareaTheme` sets the `MareaI18n` locale in `ngOnChanges` before children render, binds
  `[attr.lang]`, and components read copy synchronously from a static dictionary; no fetch,
  timer or random value participates in render.
- `formatAge()` formats `mm:ss` without `Intl`/`toLocaleString`, avoiding server/client
  locale mismatch.
- No component performs routing, data fetching or global state; numeric instrument values
  are pre-formatted by the domain layer, never locale-formatted by a component.
- The existing application keeps Angular 21 SSR, prerender and hydration; MC-18 must not
  change that architecture.

**Unverified:** hydration mismatch measurements, render timing, bundle size contribution and
performance budgets for these components. `performance-evidence.json` is missing
(`MC17-36` failure).
