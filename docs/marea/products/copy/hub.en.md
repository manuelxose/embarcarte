## 1. SEO title
MAREA HUB: onboard data gateway for your boat

## 2. Meta description
MAREA HUB brings compatible equipment data into one local vessel interface. Compatibility is checked device by device.

## 3. Hero headline
The data already on board, in one local interface.

## 4. Hero supporting statement
MAREA HUB is the onboard integration appliance of the MAREA family: it brings compatible equipment data together, publishes it on a local vessel interface and is designed so that onboard functions keep running when the internet connection is lost. It does not replace your electronics: it connects them when compatibility has been checked.

## 5. Main value proposition
Many boats already have the data: wind, depth, heading, batteries, position. What is missing is a way to bring it together and consult it in one place. MAREA HUB is a local-first appliance designed for that: it integrates what is compatible, documents what is not, and publishes a vessel data interface that other MAREA products and authorised equipment can use. Loss of internet must not stop onboard functions.

## 6. Principal customer benefits
- **One view of the vessel's data.** Compatible equipment stops being isolated across different screens and protocols.
- **Local-first operation.** Integration and local access to data do not depend on coverage; the cloud is optional, not a requirement for sailing.
- **Published compatibility, not promises.** Every device, protocol, data direction and firmware version is documented in the compatibility matrix.
- **Diagnostics and maintenance based on facts.** Connection status, configuration and failures are exposed so that an installer can work from evidence rather than assumptions.

## 7. Product overview
MAREA HUB is the onboard data gateway of MAREA: an integration appliance for vessels that already have equipment and want to make better use of it. It brings data from compatible instruments, GNSS, wind, batteries and sensors together, normalises it where the integration allows, and publishes it on a local vessel interface. MAREA NAV, MAREA AIS, MAREA SENSE and other compatible products can consume that interface according to the published matrix.

The design is **local-first**: onboard functions should remain operational if the internet connection is lost, and the commercial platform must not become a single point of failure for the vessel. The appliance does not steer the boat, does not publish a public steering-control path and is not presented as a navigation system: navigation belongs to MAREA NAV and decisions belong to the skipper.

**Product status:** complete definition (DEFINED), not available for purchase. The final list of ports, protocols and radios depends on the hardware design and will be published with the product specification once that design is frozen.

## 8. Features and capabilities

### Core software
- **Onboard data integration:** brings compatible equipment data together and makes it available on a local vessel interface.
- **Data normalisation:** where the protocol and configuration allow, unifies quantities and units so that each screen does not interpret the data in its own way.
- **Local vessel interface:** publishes data on the local network without requiring an internet connection for basic operation.
- **Connection status:** shows which devices are connected, which data is arriving and which sources have stopped responding.
- **Diagnostics and configuration:** appliance status, device identity, connection configuration and installation checks.
- **Local-first operation:** onboard functions do not depend on the availability of the commercial platform.
- **Updates and recovery:** the purchase will include a defined support period; the update policy and recovery procedure will be published with the product and confirmed by the seller before sale.
- **No steering-control path:** MAREA HUB does not steer the boat and offers no public steering-control path.

### Licensed data
- **Third-party data:** any chart, forecast, tide or current data shown through the local interface depends on the relevant entitlement and licence; MAREA HUB does not include them by default.
- **AIS-derived data:** retention, export or redistribution are subject to applicable data rights and are not presumed included.
- **Provenance and timestamp:** the local interface publishes data with its source and timestamp where the source provides them; data without provenance is not presented as valid.

### Connected instruments
- **Compatible GNSS:** incorporates position from a compatible receiver or source when the configuration permits.
- **Instruments and gateways:** wind, depth, heading, speed, batteries and other compatible data, always according to the published matrix.
- **AIS:** integrates data from a compatible AIS source; AIS reception is receive-only and does not turn MAREA HUB into a collision-avoidance system.
- **Compatible sensors:** integrates data from MAREA SENSE modules or other compatible sensors when the matrix confirms it.

### Optional hardware
- **MAREA AIS:** receive-only receiver that adds AIS traffic to the vessel.
- **MAREA DISPLAY:** fixed helm display for approved data.
- **MAREA SENSE:** family of sensors and instrumentation modules.
- **Additional cables, adapters and mounting items** required by the specific configuration when not included in the SKU, per the matrix and bill of materials.

### MAREA NAV (optional)
- **Navigation layer:** MAREA NAV consumes the local interface data when the integration is verified; MAREA HUB does not display charts and does not replace the navigation application.

### MAREA WEATHER (optional)
- **Forecast as a separate service:** MAREA WEATHER is contracted separately and publishes its source and timestamp; MAREA HUB does not include forecasts or a weather entitlement.

## 9. Realistic usage scenarios
**A boat with electronics from several eras.** The owner has an older plotter, a wind instrument from another brand and a battery charger with its own display. After reviewing the matrix, the owner installs MAREA HUB and connects what proves compatible; the local interface shows together the data that used to be separate. What is not compatible stays out and is documented as such, without promising an integration that does not exist.

**An owner installing a permitted configuration.** In a simple configuration, the owner can mount the appliance and follow the connection guide; the prior compatibility review states whether this is a permitted case and which materials are needed. For other configurations, installation is planned with EMBARCARTE or an installer.

**An installer documenting a refit.** During a refit, the installer inventories the equipment, checks firmware versions, reviews the matrix and configures MAREA HUB. Diagnostics help distinguish a badly connected cable from a device that is not sending data, and the installation documentation becomes the reference for maintenance. The duration and price of that work are quoted after the review, not announced in advance.

## 13. Compatibility
MAREA HUB compatibility is published in a matrix **per device, firmware version, protocol and data direction**. There is no universal compatibility and no device is treated as compatible because of its brand or connector.

- **Published matrix:** each row states protocol, device category, model where verified, firmware version, supported data, read or write direction, known limitations, required adapter, installation conditions, evidence and support status.
- **Signal K:** a candidate integration, not a blanket compatibility guarantee; it is checked per device and version.
- **NMEA 2000:** its status is unresolved in the programme; no NMEA 2000 certification or operational compatibility claim is made.
- **Data direction:** a read integration does not imply write or control; no steering-control path is published.
- **Versions:** a firmware update can change behaviour; compatibility is reviewed when a relevant version changes.
- **Configurations outside the matrix:** referred to specialist review and not presented as compatible.

## 14. How it works
1. **Vessel inventory:** existing equipment, protocols and firmware versions are identified.
2. **Compatibility review:** the inventory is checked against the published matrix and a valid configuration is determined.
3. **Physical installation:** the appliance is mounted, power is connected and the cables and adapters required by the configuration are routed.
4. **Configuration:** connections are set up, arriving data is checked and units and presentation are adjusted.
5. **Function checks:** expected data is verified as present, missing sources are detected and local operation is confirmed not to depend on internet.
6. **Handover and maintenance:** the installation is documented, diagnostics are explained and the support channel and warranty terms are defined.

## 15. Onboarding and installation
Installing MAREA HUB requires onboard work: power, cabling, connection to the equipment and configuration. Some simple, permitted configurations can be installed by the owner following the guide and the matrix; the others require installation by EMBARCARTE or an installer.

A compatibility review and equipment inventory are carried out before installation. No universal installation is promised, no installation duration is announced without measurement, and installation is not presented as included in the price of the appliance. Installation and configuration are quoted according to the specific vessel configuration.

## 17. Subscription and service model
MAREA HUB is defined as a hardware product with its associated software; **it does not imply a mandatory recurring subscription for local onboard functions**. Any optional data or cloud service is contracted separately and described under its own terms.

- **What it does not include:** charts, forecasts, tides, currents, mobile connectivity or third-party services.

## 19. FAQ
**Does MAREA HUB replace my plotter or my electronics?**
No. It integrates compatible equipment data and publishes a local interface; it does not replace navigation, the autopilot or existing equipment.

**Is it compatible with every piece of equipment on board?**
There is no universal compatibility. Each device, protocol and firmware version is checked in the published matrix; what falls outside is referred to specialist review.

**Do I need MAREA NAV to use MAREA HUB?**
Not for local data integration. MAREA NAV provides the navigation and planning layer and consumes the data when the integration is verified.

**What happens if internet is lost on board?**
Onboard local functions should remain operational; the design is local-first. The commercial platform and optional services may be unavailable, but local integration should not stop because of it.

**Does it include an antenna, cables or installation?**
The intended package includes the appliance and the mounting and power items specified for the SKU; it does not include the antenna, network cabling, third-party proprietary cables or installation. The SKU list and the matrix state what each configuration requires; installation is quoted separately.

**Can I install it myself?**
Only in the simple, permitted configurations stated in the guide. The rest require installation by EMBARCARTE or an installer; the prior compatibility review determines the case.

**Does MAREA HUB steer the boat?**
No. MAREA HUB has no public steering-control path and does not connect to a steering system to pilot the vessel.

**Is there a mandatory subscription?**
No for local functions. Optional data or cloud services are contracted separately and have their own terms.

**Can I export the configuration and my data?**
Configuration and local records can be exported according to the documentation. Licensed third-party data may be subject to restrictions.

**What happens if a device stops sending data?**
Diagnostics show which source has stopped responding and distinguish a missing source from valid data. If the documented checks do not resolve the issue, the support channel is opened.

**What is the NMEA 2000 status?**
No NMEA 2000 certification or operational compatibility claim is made; its status is unresolved in the programme.
